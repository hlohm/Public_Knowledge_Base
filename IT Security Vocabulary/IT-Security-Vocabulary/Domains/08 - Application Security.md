# Application Security

> AppSec is where vulnerabilities are born. Almost every term here will appear on a job description.

## Terms in this domain

- [[CORS]] — Cross-Origin Resource Sharing.
- [[CSP]] — Content Security Policy.
- [[DAST]] — Dynamic Application Security Testing.
- [[Dependency Confusion]] — Tricking a package manager into installing the attacker's public package instead of your private one.
- [[Fuzzing]] — Feeding malformed/random input to find crashes and security bugs.
- [[Hardcoded Secret]] — Credential checked into source code.
- [[IAST]] — Interactive Application Security Testing.
- [[Input Validation]] — Scrub what comes in; output encoding escapes what goes out.
- [[OWASP]] — Open Worldwide Application Security Project.
- [[OWASP ASVS]] — Application Security Verification Standard.
- [[OWASP SAMM]] — Software Assurance Maturity Model.
- [[OWASP Top 10]] — The must-know list of web application risks.
- [[Race Condition]] — Bug exploiting a timing gap.
- [[RASP]] — Runtime Application Self-Protection.
- [[Same-Origin Policy]] — Browser rule that scripts from one origin can't read data from another.
- [[SAST]] — Static Application Security Testing.
- [[SBOM]] — Software Bill of Materials.
- [[SCA]] — Software Composition Analysis.
- [[SDLC]] — Software Development Life Cycle.
- [[Secure by Design]] — Security built into the architecture.
- [[Shift Left]] — Move security activities earlier in the SDLC (design, code) where fixes are cheaper.
- [[Static Data Masking]] — Permanently replacing sensitive data with realistic but fake values to produce a safe, non-production copy
- [[STRIDE]] — Microsoft threat-modeling mnemonic: Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege.
- [[Threat Modeling]] — Structured analysis of what could go wrong with a system.
- [[Typosquatting]] — Publishing malicious packages with names close to popular ones (`reqeusts` for `requests`).
