# TDD

> **Branch:** [[08 - Software Engineering|Software Engineering]]
> **Also known as:** Test-Driven Development

A discipline of writing a failing test first, then the minimal code to pass it, then refactoring — the red-green-refactor loop.

**Context.** As much a design technique as a testing one: writing the test first forces you to design the interface from the caller's view. Divisive in practice; even skeptics often concede it shines for well-specified logic and bug fixes (reproduce-then-fix).
